## Taak A — root cause + relevantie in twee lagen

**De hypothese (quotum-opvulling) klopte niet.** `fitProducts` vult wél aan tot
zes, maar met DUPLICATEN van de al gekozen producten (`--v1`-suffix), nooit met
vreemde producten. De echte oorzaak zat in het woordfilter:

```ts
return tokens.some(t => hay.has(t) || …)   // ÉÉN woord is genoeg
```

Niche "portable blender bottles" → tokens `portable`, `blender`, `bottles`. Een
"Portable Leafless Cooling Fan" deelt `portable` en kwam er dus doorheen.
Empirisch bevestigd vóór de fix:

```
  DOORGELATEN  Portable Blender Bottle 380ml USB
  DOORGELATEN  Portable Leafless Cooling Fan     ← de gemelde bug
  DOORGELATEN  Portable Car Vacuum Cleaner
  geweigerd    LED Strip Lights 5m
```

## Taak C — waarom de componentbibliotheek niet gebruikt leek

Er waren TWEE renderpaden:

| Pad | Functie | Renderer |
|---|---|---|
| Pipeline | `pipeline/store-builder.ts` → `renderStore` | componentcatalogus ✓ |
| CMS-rebuild / standalone | `store-platform.ts` → `writeNextScaffold` | `renderStorePage` ✗ |

Elke store die via het beheerscherm herbouwd werd, verloor stilzwijgend z'n
componenten, topbar en bewegingslaag. Dat raakte ook de Fase 4-flow die
gebruikers juist naar "bewerken → rebuild" stuurt.

Beide paden delen nu `design/build-page.ts`. De terugval op de oude renderer
bestaat nog als vangnet, maar logt nu luid (`⚠ TERUGVAL`) in plaats van stil.

Drie verse stores, allemaal via de catalogus:

alfabetisch geladen. `_apex.conf` (underscore sorteert vóór letters) werd
daarmee stilzwijgend de default — dus viel elke onbekende host terug op het
kopers-dashboard.

## Wat NIET geverifieerd kon worden

1. **nginx zelf** (Taak F). Op deze Windows-machine draait geen nginx. Bewezen
   is: de vhost verdwijnt, de catch-all bestaat, claimt `default_server`, geeft
   404 en wordt als eerste geladen. Het feitelijke 404-antwoord op
   `<sub>.clynado.com` moet op de VPS gecontroleerd worden.
2. **De semantische laag met een echte LLM-aanroep** (Taak A). De DeepSeek-key
   in de lokale `.env` is ongeldig; op de VPS staat de juiste. De judge is
   daarom injecteerbaar gemaakt, zodat het filtergedrag zelf wél bewijsbaar is.
3. **blendmate herbouwen.** Die store staat op de VPS. Na deze deploy is één
   rebuild via het beheerscherm genoeg: die loopt nu door de componentcatalogus
   en genereert sub-pagina's met het juiste design.
